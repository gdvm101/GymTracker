# GymTracker

Рабочая копия для первого шага версии H. Клиент React обращается к FastAPI через Vite. PostgreSQL хранит данные, Alembic устанавливает схему, SQLAlchemy связывает её с сервером. На главной странице стенда можно проверить соединение с сервером и базой.

## Локальный запуск

Команды выполняются из каталога `GymTracker` под Linux или WSL. Для воспроизведения стенда подойдут Python 3.12 с модулем venv, PostgreSQL 16, GNU Make, Node.js 22.12 или новее и npm.

1. Один раз создайте роль и две базы на локальном PostgreSQL. Для уже подготовленного сервера используйте свои базы и учётные данные.

   ```bash
   sudo -u postgres createuser --pwprompt gymtracker
   sudo -u postgres createdb --owner=gymtracker gymtracker
   sudo -u postgres createdb --owner=gymtracker gymtracker_test
   ```

2. Выполните `make setup`. Команда установит зависимости и при первом запуске скопирует `backend/.env.example` в `backend/.env`. Подставьте пароль созданной роли в `DATABASE_URL` и `TEST_DATABASE_URL`. В образце обе базы находятся на порту 5432. Для версии H оставьте `FEATURES=` и `AI_ENABLED=false`.

3. Подготовьте данные и запустите проверки.

   ```bash
   make migrate
   make seed
   make test
   ```

4. В двух терминалах из корня выполните `make backend` и `make frontend`. Откройте [GymTracker](http://localhost:5173). Кнопка «Проверить связь» повторяет запрос к серверу. Для сборки клиента выполните `make build`. Результат появится в `frontend/dist/`.

## Что входит в шаг 1

| Часть | Реализация |
| --- | --- |
| Схема | Миграция `0001` создаёт 9 основных таблиц, таблицы настроек и измерений, а также 5 таблиц расширений, предусмотренных архитектурой. Ограничения проверяют ссылки, номера и числовые значения. Для редактирования порядка упражнений предусмотрено отложенное ограничение `uq_program_position`. |
| Справочник | Миграция заполняет 6 упражнений. «Жим гантелей» имеет ID 10, «Тяга верхнего блока» — 11. Значения 1–99 отведены начальным записям, обычные ID начинаются со 100. Повторный `make seed` восстанавливает только отсутствующие строки и сохраняет редакторские правки. |
| API | Служебный `GET /api/v1/health` выполняет запрос к таблице упражнений и возвращает `{"status":"ok"}`. При потере связи с PostgreSQL ответ содержит `503 STORAGE_UNAVAILABLE`. Для ошибок используется формат `{error: {code, message, details}}`, для ошибок ввода возвращается путь поля. Идентификатор запроса приходит в `X-Request-ID`. |
| Клиент | Страница стенда показывает результат запроса к API и позволяет повторить проверку. Общий HTTP-клиент поддерживает JSON, cookie того же origin, заголовок CSRF, отмену запроса, ответ 204 и серверный формат ошибок. |
| Тесты | `pytest` проверяет сервер, `Vitest` — клиент. Интеграционные тесты используют `TEST_DATABASE_URL` и получают отдельную схему для каждого случая. После прогона фикстура удаляет только созданную ею схему. |

## Результаты проверки 20.11.2026

Прогон выполнен из чистой распаковки под Linux x86_64. Использованы Python 3.12.14, PostgreSQL 16.2, Node.js 24.22.3 и npm 11.19.1. Рабочая и тестовая базы принадлежат обычной роли `gymtracker`. Конфигурация H использует часовой пояс Europe/Moscow, пустой `FEATURES` и `AI_ENABLED=false`. Версия приложения 0.1.0, ревизия схемы 0001.

| Проверка | Фактический результат |
| --- | --- |
| `make setup`, `make migrate`, два запуска `make seed` | Окружение установилось. После миграции в справочнике 6 упражнений. Каждый повторный запуск добавил 0 строк. |
| `make test-unit` | Прошли 13 серверных проверок. UT-18 вернул `INVALID_INPUT` и путь `exercises.0.sets.1.weight`. |
| `make test-integration` | Прошли 8 проверок на PostgreSQL, включая откат и повторное применение миграции, две одновременные загрузки справочника, перестановку упражнений и сохранность тренировки после удаления программы. |
| `make test-ui` и `make build` | Прошли 6 проверок HTTP-клиента. Vite собрал приложение в `frontend/dist/`. |
| `alembic check` | Модели SQLAlchemy соответствуют установленной миграции. |
| Chromium 153 и Firefox 153 | В обоих браузерах на ширине 1280 и 390 пикселей запрос из интерфейса получил 200, горизонтальной прокрутки нет. При остановке PostgreSQL страница показала ошибку 503. После запуска базы кнопка «Проверить связь» восстановила состояние без перезагрузки. |

## Где продолжать

- `backend/app/` — модели, конфигурация, обработчики ошибок, инфраструктура API и загрузка справочника.
- `backend/migrations/` — версия схемы и настройки Alembic.
- `frontend/src/` — компоненты React и HTTP-клиент.
- `backend/tests/` и `frontend/src/api/httpClient.test.js` — автоматические проверки.
- `docs/` — исходная документация и макеты из архива. [Старт разработки](docs/00_Start.md) · [архитектура](docs/01_Architecture.md) · [план тестирования](docs/03_Test_Plan.md).
